# Релиз

Как собрать и раздать версию офицерам. Само приложение раздаётся установщиком,
сервер синхронизации — отдельно и один раз (см.
[sync-worker/README.md](../sync-worker/README.md)).

## Версия

Три места, все три должны совпадать:

| Файл | Поле |
| --- | --- |
| [package.json](../package.json) | `version` |
| [src-tauri/tauri.conf.json](../src-tauri/tauri.conf.json) | `version` |
| [src-tauri/Cargo.toml](../src-tauri/Cargo.toml) | `version` |

Ни от одного из трёх номер не выводится автоматически — синхронизация ручная.
Установщик и имя exe берут версию из `tauri.conf.json`, поэтому если забыть его,
файл соберётся с прежним номером в имени, а `package.json` разойдётся с ним.

## Что нужно на машине для сборки

Node.js 20+, Rust stable, [системные зависимости Tauri](https://tauri.app/start/prerequisites/)
(на Windows — MSVC build tools и WebView2, обычно уже есть). Для NSIS-инсталлятора
Tauri сам подтягивает `makensis` при первой сборке.

## Сборка

```bash
npm install
npm run tauri build
```

Внутри: `vue-tsc --noEmit` → `vite build` → компиляция Rust в release → упаковка.
Любая из проверок падает — сборки не будет, слать пользователю нечего.

Результат на Windows — в `src-tauri/target/release/bundle/`:

- `msi/easy-pl_<версия>_x64_en-US.msi`
- `nsis/easy-pl_<версия>_x64-setup.exe`

Раздавать проще `.exe` — не просит прав администратора и ставится через один
диалог. `.msi` пригождается, если у получателя корпоративная политика требует
именно его.

## Иконка не переembedится сама

`tauri-build` зашивает `icons/icon.ico` в ресурсы exe из build-скрипта, а
перезапуск скрипта Cargo отслеживает по `tauri.conf.json`, не по самим файлам
иконок. Подменили иконки в [src-tauri/icons/](../src-tauri/icons/), конфиг не
трогали — соберётся старая версия иконки, молча и без единого предупреждения.
После `tauri icon` (или ручной подмены `icon.ico`) обязателен:

```bash
cargo clean -p easy-pl
npm run tauri build
```

## Проверка перед раздачей

```bash
npm test              # 130+ тестов, схема и репозитории — на настоящем SQLite
npx vue-tsc --noEmit   # типы; npm run build делает то же самое перед vite build
```

Оба шага уже входят в `npm run tauri build`, но по отдельности быстрее при
итерации. Ручная проверка: поставить `.exe` на чистой машине (или в отдельной
папке — установщик не требует деинсталляции старой версии), убедиться, что
открывается окно нужного размера и с нужной иконкой на панели задач.

## Раздача

Файл `.exe` — самому пользователю (почта, диск, мессенджер) вместе с кодом
подключения `EASYPL1-…`, если сервер синхронизации уже поднят и не зашит в
`.env` при сборке. Установка не требует прав администратора и не трогает
существующую базу `%APPDATA%\com.easypl.app\easy-pl.db` — обновление версии на
компьютере пользователя безопасно ставить поверх.

Если в `.env` при сборке был указан `VITE_SYNC_URL`/`VITE_SYNC_TOKEN` — сборка
уже подключена, код подключения раздавать не нужно (см.
[README.md](../README.md#настройки-сборки--env)).

## Обновление у пользователя

Новую версию `.exe` ставят поверх старой — установщик сам находит и заменяет
предыдущую. База и ключ синхронизации не трогаются. Если менялась схема —
миграции применятся автоматически при первом запуске новой версии, откатывать
их вручную не нужно и нельзя (см. [DATABASE.md](DATABASE.md#миграции)).

## Если сборка не проходит

- `vue-tsc` находит ошибки типов — значит, они есть; `as` и `@ts-ignore` в этом
  проекте запрещены как способ их обойти (см. [CLAUDE.md](../CLAUDE.md)).
- Rust не компилируется на чистой машине — проверьте системные зависимости по
  ссылке выше, чаще всего не хватает MSVC build tools.
- `light`/`candle` (WiX, для `.msi`) не найден — переустановите через
  `rustup` заново или соберите только NSIS-таргет:
  `npm run tauri build -- --bundles nsis`.
