# Руководство

Как вести осады в easy-pl: от первого запуска до закрытия события. Почему
жеребьёвка устроена именно так — в [SPEC.md](SPEC.md).

## Первый запуск

1. **Справочники → Синхронизация.** Вставьте код подключения `EASYPL1-…` от
   офицера, у которого приложение уже настроено, и нажмите «Подключиться».
   Приедет весь справочник и все осады. Если сборку собирали с `.env`, шаг
   пропускается — приложение уже подключено.
2. **Справочники → Рейды.** Заведите рейды гильдии. Игрок может быть и без
   рейда — это отдельная группа со своими местами, а не «никуда не годные».
3. **Гильдия.** Проверьте состав: класс, рейд, ник в Discord. Ник нужен только
   для импорта заявок по реакциям — без него игрок просто не опознается
   автоматически, руками привязать можно.

Дальше правки уезжают сами: при запуске, через полминуты тишины после
последнего изменения и при закрытии окна. Значок в шапке показывает состояние
обмена; кнопка «Синхронизировать» в справочниках — на случай «хочу прямо сейчас».

## Осада

### Создание

**Осады → Новая осада.** Название, дата и **места по рейдам** — сколько человек
выводит каждый рейд. Общее число мест приложение считает само, вводить его
негде: это сумма квот.

Группе «Без рейда» места тоже надо выделить, иначе неприписанные игроки в состав
не попадут — их просто некуда сажать.

### Заявки

На странице осады, пока она в статусе «Набор состава»:

| Действие | Что делает |
| --- | --- |
| Галочка «Заявился» | игрок участвует в жеребьёвке |
| Тумблер «Точно идёт» | место вне жребия, гарантированно |
| «Заявить всех» / «Снять всех» | оптом, для гильдий, где ходят почти все |
| «Посмотреть по реакциям» | забрать заявки из Discord |

Избранные игроки (★ в списке гильдии) получают «точно идёт» автоматически в
момент заявки — на всех осадах, каждый раз.

**Импорт из Discord.** Выберите канал → сообщение → реакцию, приложение покажет,
кто отреагировал. Опознанных заявляет сразу, неопознанных предлагает привязать
к игроку руками — привязка запоминается, второй раз спрашивать не будет.
Настраивается в **Справочники → Discord**.

### Жеребьёвка

Кнопка «Провести жеребьёвку». Каждый рейд разыгрывает свою квоту среди своих
заявившихся: сначала места занимают «точно идёт», остальные разыгрываются
взвешенным жребием — чем больше долг, тем выше шанс.

Недобор рейда никуда не уходит: не хватило желающих — места остаются пустыми,
их закроет пати-лидер своим решением. Соседнему рейду они не достаются.

**Если обязательных больше, чем мест**, окно подтверждения покажет это и
предложит три выхода:

- **Вывести сверх квоты** — рейду добавится столько мест, сколько нужно, общее
  число мест вырастет;
- **Вывести в рейде** — отправить игрока в рейд, где места есть. Это только на
  эту осаду: рейд игрока в справочнике не меняется, в составе он помечен
  значком «разово», крестик на значке возвращает его в свой рейд;
- **Снять «точно идёт»** — прямо из того же окна.

Жребий воспроизводим: у осады есть `seed`, и по нему результат пересчитывается
один в один. «Переиграть жребий» стирает прошлый результат вместе с отметками
явки и разыгрывает заново с новым seed.

### Явка

После жеребьёвки у каждого в составе две кнопки — «Пришёл» и «Нет».

Отметили «Нет» — место освободилось, и любому заявившемуся **из того же рейда**
становится доступна кнопка «В состав». Заменивший считается прошедшим вне
жребия: пришёл — долг не меняется.

### Закрытие

«Закрыть осаду» пересчитывает долги по итогам и запирает событие: менять больше
ничего нельзя. Если кого-то не отметили, приложение скажет, скольких, — долг им
посчитается как «место было, явка неизвестна».

## Долг

Долг — это счётчик справедливости, а не наказание. Он двигает вес в жеребьёвке:
вес = `max(0.25, 1 + долг)`, предел ±10.

| Что случилось | Долг |
| --- | --- |
| Заявился, не прошёл | `+share` — доля свободных мест своего рейда |
| Прошёл по жребию (пришёл или нет) | `−(1 − share)` |
| Прошёл вне жребия и пришёл | без изменений |
| Прошёл вне жребия и не пришёл | `−2 × (1 − share)` |
| Не заявился | без изменений |

Положительный долг — «гильдия должна человеку место», он идёт первым в очереди.
Отрицательный — уже отходил своё. Подсказка со знаком вопроса рядом с колонкой
«Долг» повторяет ту же таблицу внутри приложения.

Долг можно поправить руками в списке гильдии — на случай договорённостей,
которых приложение не видит.

## Гильдия

Строки — игроки, колонки — класс, рейд, долг, посещаемость. Звёздочка делает
игрока избранным: такие всегда идут вне жребия.

Ушедший из гильдии удаляется целиком, вместе со следами в прошлых осадах —
состояния «вышел» нет. Вернулся — заводится заново с нулевым долгом.

## Статистика

Заполнение осад, явка по рейдам и по людям, графики по датам. Под каждым
графиком — таблица с теми же числами: график для «видно тренд», таблица для
«назови точное значение».

Численность рейда считается по справочнику, а участие — по тому рейду, в
котором игрок реально был на той осаде: разово выведенный засчитывается
принявшему рейду.

## Справочники

- **Классы** — комбинация класса и ветки («Ведьма (Традиция)»). Название можно
  переименовать под себя, у игроков подпись поменяется сама.
- **Рейды** — то же самое. Рейд, назначенный игрокам, удалить нельзя, только
  отключить: иначе поедут ссылки в прошлых осадах.
- **Синхронизация** — код подключения, состояние обмена, «Забыть прогресс»
  (перечитать всё с сервера заново).
- **Discord** — подключение бота, выбор сервера и эмодзи заявки.
- **Тема** — оформление приложения.

## Если что-то пошло не так

| Симптом | Что это |
| --- | --- |
| В шапке «нет связи» | сервер синхронизации недоступен — чаще всего VPN. Правки не потеряются, уедут при следующем удачном обмене |
| «Сервер отклонил ключ» | код подключения устарел — попросите новый |
| Осада не разыгрывается: «ни одному рейду не выделено мест» | квоты нулевые — задайте их в «Изменить» |
| В Discord пустой список участников | в Developer Portal не включены привилегированные интенты — см. [SYNC.md](SYNC.md#discord) |
| Данные разъехались между компьютерами | «Забыть прогресс» и синхронизация: побеждает более поздняя правка |
