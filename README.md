# easy-pl

Настольное приложение для офицера гильдии Black Desert: справочник состава,
жеребьёвка мест на осаду по рейдам, учёт явки и долга. Работает без сервера —
данные лежат в SQLite рядом с приложением, а между компьютерами офицеров
разъезжаются сами через свой Cloudflare Worker.

Tauri 2 (Rust) + Vue 3 + TypeScript.

## Что оно делает

| Экран | Зачем |
| --- | --- |
| **Осады** | список событий, создание, места по рейдам |
| **Осада** | заявки, жеребьёвка, состав, явка, закрытие с пересчётом долга |
| **Гильдия** | игроки: класс, рейд, Discord, долг, избранные |
| **Статистика** | заполнение осад, явка по рейдам и людям, графики и те же числа таблицей |
| **Справочники** | классы и рейды, подключение к обмену, Discord, тема |

Главное, ради чего всё затевалось, — жеребьёвка, которая не даёт одним и тем же
людям сидеть дома. У каждого игрока есть долг: пропустил осаду не по своей
вине — вес в жребии растёт, сходил — падает. Алгоритм и обоснование —
в [SPEC.md](docs/SPEC.md).

## Установка

Готовая сборка — `easy-pl_<версия>_x64-setup.exe` (или `.msi`). Ставится без
прав администратора, обновление ставится поверх, база не трогается.

База лежит в `%APPDATA%\com.easypl.app\easy-pl.db` — это единственное, что стоит
скопировать при переезде на другой компьютер. Ключ синхронизации хранится
отдельно, в диспетчере учётных данных Windows, и с базой не переезжает: его
проще ввести заново кодом подключения.

Первый запуск: **Справочники → Синхронизация** → вставить код `EASYPL1-…`,
который дал офицер, у которого приложение уже настроено. После этого правки
разъезжаются сами, кнопку жать не нужно.

## Разработка

Нужны Node.js 20+, Rust stable и [системные зависимости Tauri](https://tauri.app/start/prerequisites/).

```bash
npm install
npm run tauri dev
```

| Команда | Действие |
| --- | --- |
| `npm run tauri dev` | приложение в режиме разработки |
| `npm run tauri build` | сборка дистрибутива |
| `npm run dev` | только фронтенд в браузере, http://localhost:1420 |
| `npm run build` | type-check (`vue-tsc`) и сборка фронтенда |
| `npm test` | тесты (Vitest); схема и репозитории гоняются на настоящем SQLite |
| `npm run worker` | сервер синхронизации локально (Wrangler) |

В браузере (`npm run dev`) работает только вёрстка: базы и команд Rust там нет,
любой экран с данными упадёт на первом же запросе.

## Настройки сборки — `.env`

В корне лежит `.env` (в гит не попадает, образец — `.env.example`). Заполнять его
необязательно: без него приложение просит подключиться вручную.

| Ключ | Что делает |
| --- | --- |
| `VITE_SYNC_URL` | адрес сервера синхронизации — подставится сам при первом запуске |
| `VITE_SYNC_TOKEN` | ключ синхронизации — если указан, приложение стартует уже подключённым |

Заполнены оба — собранное приложение приезжает к людям настроенным: ни адреса,
ни кода подключения вводить не нужно, сразу видна кнопка «Синхронизировать».

**Это не хранилище секретов.** Vite подставляет значения `VITE_*` прямо в код на
этапе сборки, поэтому всё, что здесь написано, лежит открытым текстом внутри
установщика — распаковать и прочитать может кто угодно. Класть сюда `DISCORD_TOKEN`
нельзя: токен бота живёт секретом на Cloudflare и на компьютеры не попадает вовсе.
`VITE_SYNC_TOKEN` в этом смысле — осознанный размен: он и так уезжает всем внутри
кода подключения, но со сборкой расходится шире, чем строка в личном сообщении.
Не хотите — оставьте пустым и раздайте код подключения.

Значения читаются один раз, при первом запуске, и сохраняются в базу приложения.
Меняете адрес после раздачи сборки — людям придётся подключиться заново, из `.env`
он второй раз не подхватится.
