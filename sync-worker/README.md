# Сервер синхронизации

Общая база для easy-pl: хранит записи всех машин и раздаёт каждой то, что изменилось
с её прошлого захода. Cloudflare Worker + база D1, бесплатного тарифа хватает
с запасом — на гильдию в 44 человека выходит порядка десятков запросов в сутки.

## Развернуть — одна кнопка, без консоли

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/SWDevStudio/easy-pl/tree/main/sync-worker)

Нажмите кнопку и пройдите четыре экрана в браузере:

1. **Вход в Cloudflare.** Если аккаунта нет — зарегистрируйтесь, карта не нужна.
2. **Подключение GitHub.** Cloudflare скопирует этот сервер в ваш аккаунт GitHub,
   чтобы потом собирать его сам. Разрешите доступ, когда попросит.
3. **Ключ синхронизации.** В поле `SYNC_TOKEN` впишите длинную случайную строку —
   это общий пароль для всех, кто пользуется приложением. Придумайте что-то вроде
   `guild-sync-8f3a1c9d7e2b4a6f`, только длиннее и не из этой инструкции.
4. **Deploy.** База D1 создаётся автоматически, таблицы сервер заводит себе сам
   при первом обращении. Ничего запускать руками не нужно.

Когда сборка закончится, Cloudflare покажет адрес вида
`https://easy-pl-sync.ваш-аккаунт.workers.dev`. Адрес и ключ понадобятся один раз.

## Подключить приложение

**Тому, кто разворачивал сервер.** Настройки → Синхронизация → «Я завожу общую базу
первым» → вставьте адрес и ключ → «Подключиться». Приложение сразу проверит связь
и выгрузит текущую базу.

**Всем остальным.** Первый нажимает «Скопировать код подключения» и присылает
получившуюся строку (`EASYPL1-…`) остальным. Они вставляют её в Настройки →
Синхронизация → «Код подключения» → «Подключиться». Адрес и ключ приложение
достанет из кода само.

Дальше синхронизация — это кнопка «Синхронизировать» на той же панели.

## Обновить сервер

Кнопка «Deploy» скопировала сервер в ваш GitHub, связи с исходным репозиторием
у копии нет. Если здесь выйдут исправления, их нужно перенести руками: откройте
свою копию на GitHub, замените содержимое `src/index.ts` новым и сохраните —
Cloudflare пересоберёт и выложит сам, тоже без консоли.

## Если предпочитаете консоль

```bash
npm install
npx wrangler login
npx wrangler d1 create easy-pl-sync   # id из вывода — в wrangler.jsonc
npx wrangler secret put SYNC_TOKEN
npx wrangler deploy
```

Отдельного файла со схемой нет: таблицы создаёт сам Worker при первом запросе
(`CREATE TABLE IF NOT EXISTS`), так что путь через кнопку и путь через консоль
дают одинаковый результат.

## Как это устроено

Один эндпоинт `POST /sync`. Клиент присылает номер ревизии, на котором остановился,
и свои изменения; получает новую порцию чужих.

```json
{ "since": 42, "changes": [ { "entity": "player", "uid": "…", "updatedAt": "…", "deleted": false, "data": {} } ] }
```

Записи лежат парами «сущность + идентификатор» с JSON-телом, поэтому схему на
сервере не придётся менять, когда в приложении появятся новые поля.

**Ревизия выдаётся вместе с записями, в одной транзакции.** Иначе номер успевал бы
закрепиться раньше, чем строки, которые он помечает: другой клиент забирал бы
изменения «до» этого номера, не увидев их, и больше уже никогда не запросил.
По той же причине клиент двигает свой курсор по номерам реально полученных
записей, а не по числу, которое вернул сервер.

**Ответ отдаётся страницами** (`hasMore`), и клиент выгружает свои изменения
пачками. Без этого первая же синхронизация большой базы молча теряла бы хвост.

**Конфликты решаются по времени правки:** запись перезаписывается, только если
пришедшая версия новее сохранённой (`excluded.updated_at > records.updated_at`).
Настоящего слияния полей нет — при одновременной правке одной записи с двух машин
победит более поздняя. Время приходит с машины, которая правила, поэтому сервер
отклоняет отметки, убежавшие вперёд больше чем на 15 минут: сбитые часы иначе
делали бы записи неперезаписываемыми навсегда.

**Удаления передаются надгробиями** — записью с флагом `deleted`. Без них удаление
на одной машине воскресало бы при следующей синхронизации с другой.

**Идентификаторы глобальные.** Локальные `id` в SQLite автоинкрементные и на разных
машинах столкнулись бы, поэтому каждая запись несёт `uid`. У сид-данных он выводится
из естественного ключа и получает фиксированную отметку времени: иначе свежая
установка выглядела бы «новее» и откатывала бы правки справочника на всех машинах.

## Ограничения

- Ключ один на всех: он подтверждает право писать в общую базу, но не различает,
  кто именно написал.
- Из России Cloudflare доступен нестабильно — нужен VPN, как и для Discord.
- Репозиторий должен оставаться публичным: кнопка «Deploy» не умеет работать
  с приватными.
