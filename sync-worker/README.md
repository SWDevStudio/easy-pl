# Сервер синхронизации

Cloudflare Worker + база D1. Держит общий набор записей и раздаёт клиентам изменения
с момента их последней синхронизации. Бесплатного тарифа хватает с огромным запасом:
на гильдию в 44 человека получается порядка десятков запросов в сутки при лимите
100 000 запросов и 100 000 записанных строк в день.

## Что нужно один раз

Понадобится аккаунт Cloudflare и Node.js. Все команды — из этой папки, начиная с
`npm install` (ставит wrangler — консоль Cloudflare).

**1. Войти в Cloudflare**

```bash
npx wrangler login
```

**2. Создать базу**

```bash
npx wrangler d1 create easy-pl
```

Команда напечатает `database_id`. Впишите его в `wrangler.toml` вместо
`ЗАПОЛНИТЬ_ПОСЛЕ_СОЗДАНИЯ_БАЗЫ`.

**3. Создать таблицы**

```bash
npx wrangler d1 execute easy-pl --remote --file=schema.sql
```

**4. Задать общий ключ**

Придумайте длинную случайную строку — её будут вводить в приложении все, кто
пользуется общей базой.

```bash
npx wrangler secret put SYNC_TOKEN
```

**5. Выложить**

```bash
npx wrangler deploy
```

В конце команда напечатает адрес вида `https://easy-pl-sync.ваш-аккаунт.workers.dev`.
Его и ключ вставьте в приложении: **Справочники → Синхронизация**.

## Как это работает

Один эндпоинт `POST /sync`. Клиент присылает свою последнюю известную ревизию и
локальные изменения, получает в ответ новую ревизию и всё, что изменилось на сервере
с его прошлого захода.

```json
{ "since": 42, "changes": [ { "entity": "player", "uid": "…", "updatedAt": "…", "deleted": false, "data": {} } ] }
```

Записи хранятся как пары «сущность + идентификатор» с JSON-телом, поэтому схему
на сервере менять не придётся, когда в приложении добавятся поля.

**Разрешение конфликтов — по времени правки.** Запись перезаписывается, только если
пришедшая версия новее сохранённой: условие `excluded.updated_at > records.updated_at`
прямо в `INSERT ... ON CONFLICT`. Одновременная правка одной записи с двух машин
означает, что победит более поздняя, а не обе — настоящего слияния полей здесь нет
и для гильдейского учёта не нужно.

**Удаления передаются надгробиями.** Клиент, удаливший запись, пишет её в таблицу
`tombstones` и отправляет с флагом `deleted`. Без этого удаление на одной машине
воскресало бы при следующей синхронизации с другой.

**Идентификаторы глобальные.** Локальные `id` в SQLite автоинкрементные и на разных
машинах неизбежно столкнулись бы, поэтому каждая запись несёт `uid`. У сид-данных
(классы, стартовый состав) он выводится из естественного ключа, чтобы две свежие
установки не создали дубликаты одного и того же класса.

## Ограничения

- Токен один на всех: он подтверждает право писать в общую базу, но не различает,
  кто именно написал. Для приватного инструмента на несколько человек этого хватает;
  для чего-то большего нужны отдельные учётки.
- Из России Cloudflare доступен нестабильно — работает через VPN, как и Discord.
